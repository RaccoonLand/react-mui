# 4. PipelineHooksProvider

The provider that hands toast + loading adapters to `usePipelineQuery` / `usePipelineMutation`.

- **Package:** `@raccoonland/pipeline-client`
- **File:** `src/PipelineHooks.tsx`

## Why an adapter instead of a hard dependency

The package used to import `@raccoonland/feedback` directly. That made it impossible to consume from an app that used
a different toast/loading stack, and it also made the package's tests carry an unrelated UI dependency graph. The
`PipelineHooksAdapter` is the smallest surface the hooks need — nothing more.

```ts
export type PipelineToastAdapter = {
  showError: (message: string) => void
  showWarning: (message: string) => void
}

export type PipelineLoadingAdapter = {
  withLoading: <T>(
    action: () => Promise<T>,
    options?: { scope?: 'global' | 'local'; message?: string },
  ) => Promise<T>
}

export type PipelineHooksAdapter = {
  toast: PipelineToastAdapter
  loading: PipelineLoadingAdapter
}
```

## Default adapter

If no provider is mounted, the hooks fall back to a silent no-op:

```ts
const defaultAdapter: PipelineHooksAdapter = {
  toast: { showError: () => {}, showWarning: () => {} },
  loading: { withLoading: (action) => action() },
}
```

This means requests still run (and still throw), they just do not produce any UI. Useful for tests and headless
usage.

## Wiring in a host app

```tsx
// app/PipelineHooksBridge.tsx
import { PipelineHooksProvider, type PipelineHooksAdapter } from '@raccoonland/pipeline-client'
import { useLoading, useToast } from '@raccoonland/feedback'
import { useMemo, type ReactNode } from 'react'

export function PipelineHooksBridge({ children }: { children: ReactNode }) {
  const { showError, showWarning } = useToast()
  const { withLoading } = useLoading()

  const adapter = useMemo<PipelineHooksAdapter>(
    () => ({
      toast: { showError, showWarning },
      loading: { withLoading },
    }),
    [showError, showWarning, withLoading],
  )

  return <PipelineHooksProvider adapter={adapter}>{children}</PipelineHooksProvider>
}
```

Mount the bridge **inside** your toast/loading providers so its hooks resolve, and **above** any component that
uses `usePipelineQuery` / `usePipelineMutation`.

## Contract details

- `withLoading` returns the same `Promise<T>` the action returned — the hooks awaits it so cancellation and
  errors bubble through unchanged.
- `showError` / `showWarning` receive already-localized strings. Do not localize inside the package.
- `scope` on `withLoading` differentiates a full-screen backdrop (`global`) from a component-level busy signal
  (`local`). Adapters may treat both as global if that fits their UI.
