# 1. Overview

`@raccoonland/pipeline-client` is the React counterpart of the dotnet request-processing pipeline. It parses the
`PipelineResponse` envelope produced by a RaccoonLand backend, exposes ergonomic TanStack Query hooks, and lets the
host app wire in whichever toast / loading UI it prefers.

- **Package:** `@raccoonland/pipeline-client`
- **Peer deps:** `react`, `react-dom`, `@tanstack/react-query`, `axios`

## Why this exists

Front-ends talking to a RaccoonLand API repeat the same three steps on every request:

1. Recognize the `{ result, errors, warnings, statusHint }` envelope.
2. Translate `errors` into UI (toasts, banners, form field errors) and `warnings` into non-blocking notices.
3. Toggle a loader while the request is in flight.

Doing this by hand once per request drifts quickly — some call sites forget the loader, others toast every warning
as an error, others swallow abort errors and confuse React Query's retry logic. This package centralizes all three
concerns behind two hooks (`usePipelineQuery`, `usePipelineMutation`) and a minimal client factory.

## Layering

```text
+---------------------------------------------+
|  Host app (Backoffice, admin, ...)          |
|  - creates its own axios instance           |
|  - wires PipelineHooksProvider (adapters)   |
|  - localizes UI messages                    |
+---------------------------------------------+
                    |
                    v
+---------------------------------------------+
|  @raccoonland/pipeline-client               |
|  - createPipelineClient(axios)              |
|  - usePipelineQuery / usePipelineMutation   |
|  - PipelineApiError / NetworkError / ...    |
+---------------------------------------------+
                    |
                    v
+---------------------------------------------+
|  RaccoonLand API (dotnet)                   |
|  - returns PipelineResponse<T>              |
+---------------------------------------------+
```

The package is **UI-agnostic**: it never imports `@raccoonland/feedback`, MUI, or notistack. Toasts and loaders are
supplied by the host through the [`PipelineHooksProvider`](4.PipelineHooksProvider.md) adapter contract.

## What is (and isn't) included

Included:

- Envelope parsing → typed `PipelineResult<T>` (`4.` = errors thrown, `2xx` warnings surfaced).
- Axios binding via `createPipelineClient(axiosInstance)`.
- TanStack Query hooks that glue together the executor, adapters, and error mapping.
- A pure `normalizePipelineData` helper for camelCasing server payloads.
- Optional `reportSystemError(error, context)` hook so hosts can wire Sentry/OTel later.

Not included:

- Auth / token refresh. Attach those to your axios instance.
- Toast / loading UI. Provide adapters via `PipelineHooksProvider`.
- i18n. Localized error/warning messages come from the server; UI strings come from `PipelineUiMessagesProvider`.
