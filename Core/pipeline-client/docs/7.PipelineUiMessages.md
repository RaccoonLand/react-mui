# 7. PipelineUiMessages

Localized strings the hooks show for non-server errors (network, invalid envelope, unknown).

- **Package:** `@raccoonland/pipeline-client`
- **File:** `src/PipelineUiMessages.tsx`

## Contract

```ts
export type PipelineUiMessages = {
  networkError: string
  invalidPipelineResponse: string
  unknownError: string
}
```

Defaults are English:

```ts
const defaultMessages: PipelineUiMessages = {
  networkError: 'Could not reach the server',
  invalidPipelineResponse: 'The server returned an invalid response',
  unknownError: 'An unknown error occurred',
}
```

## Provider

```tsx
<PipelineUiMessagesProvider messages={{
  networkError: t('networkError'),
  invalidPipelineResponse: t('invalidPipelineResponse'),
  unknownError: t('unknownError'),
}}>
  {children}
</PipelineUiMessagesProvider>
```

- Pass a **stable reference** (memoize it) if the parent re-renders frequently. The provider deep-merges the supplied
  partial with `defaultMessages`, so any subset is fine.
- The provider itself memoizes its context value on the incoming `messages` reference, so a stable input means a
  stable context and no downstream re-renders.

## Why these three keys and not the server's error messages

Server errors flow through `PipelineApiError.errors[]` where each item already carries a localized
`message` (the backend owns that translation via `RaccoonLand.Localization`). The three keys here cover only
categories the server cannot produce a message for — because the request never got there or the response was
unparseable.

## Wiring with `useLocale` (sample pattern)

```tsx
const { t } = useLocale()

const pipelineMessages = useMemo<PipelineUiMessages>(
  () => ({
    networkError: t('networkError'),
    invalidPipelineResponse: t('invalidPipelineResponse'),
    unknownError: t('unknownError'),
  }),
  [t],
)

<PipelineUiMessagesProvider messages={pipelineMessages}>
  <PipelineHooksBridge>{children}</PipelineHooksBridge>
</PipelineUiMessagesProvider>
```
