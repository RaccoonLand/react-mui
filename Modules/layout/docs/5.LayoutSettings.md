# 5. LayoutSettings — context, panel, and fullscreen

Persistent user preferences for the shell: orientation, sidebar density, and theme mode (via
[`ThemeModeProvider`](../../theme/docs/4.ThemeModeProvider.md)).

- **Package:** `@raccoonland/layout`
- **Files:** `src/LayoutSettingsContext.tsx`, `src/LayoutSettingsPanel.tsx`, `src/useAppFullscreen.ts`, `src/sidebarOrientation.ts`, `src/sidebarVerticalDensity.ts`

## LayoutSettingsProvider

Owns two pieces of state — orientation and vertical density — with `localStorage` persistence. Mounted by
`BackofficeLayout` internally; you rarely mount it yourself.

```ts
type LayoutSettingsContextValue = {
  orientation: 'vertical' | 'horizontal'
  setOrientation: (next) => void
  toggleOrientation: () => void
  density: 'expanded' | 'compact' | 'collapsed'
  setDensity: (next) => void
  cycleDensity: () => void
}

const { orientation, density, cycleDensity, toggleOrientation } = useLayoutSettings()
```

### Storage keys

Both are overridable per-app so multi-app origins don't collide:

```tsx
<BackofficeLayout
  orientationStorageKey="myapp-sidebar-orientation"
  densityStorageKey="myapp-sidebar-density"
  {...rest}
/>
```

Defaults are `DEFAULT_ORIENTATION_STORAGE_KEY` / `DEFAULT_DENSITY_STORAGE_KEY` (see the corresponding files).

### Density cycle

`cycleDensity()` advances through `expanded → compact → collapsed → expanded`. The header's leading button binds to
this. When orientation is `horizontal` (or the viewport is mobile) density has no visible effect and the settings
panel disables the density card.

## LayoutSettingsPanel

Presentational settings page — a set of `OptionCard`s for orientation, density, and theme mode. Uses
`useLayoutSettings()` + `useThemeMode()`. Mount inside `BackofficeLayout` (needs both contexts).

```tsx
<Route path="/settings/layout" element={<LayoutSettingsPage />} />

function LayoutSettingsPage() {
  return (
    <Page title={t('layoutSettings')} breadcrumbs={crumbs}>
      <LayoutSettingsPanel />
    </Page>
  )
}
```

## useAppFullscreen

Wraps the browser Fullscreen API with:

- `toggleFullscreen()` — enters/exits, toasts a warning if the browser blocks it.
- `isFullscreen` — reactive boolean, kept in sync via `fullscreenchange`.
- **F11 interception** — the hook installs a capture-phase `keydown` listener and routes F11 through the same
  toggle. This unifies the two entry points (header button + F11) so the app always uses the JS Fullscreen API,
  not the browser's native full-screen mode.

Callers get `{ isFullscreen, toggleFullscreen }` and the header wires them into an icon button.

## Design notes

- The provider caches state via `useState` with a lazy initializer that reads storage synchronously — no flicker
  on mount. Writes go through the `setOrientation` / `setDensity` `useCallback`s so external subscribers see
  stable references.
- The settings panel intentionally lives in the same package as the settings context so both change together;
  external apps can still compose their own settings UI on top of `useLayoutSettings()` if they want to add more
  items (e.g. RTL/LTR toggle).
