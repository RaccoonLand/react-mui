# 4. Sidebar (vertical & horizontal)

Two independent sidebar implementations that share a nav-item contract.

- **Package:** `@raccoonland/layout`
- **Files:** `src/SidebarVertical.tsx`, `src/SidebarHorizontal.tsx`, `src/sidebarVerticalDensity.ts`, `src/sidebarOrientation.ts`, `src/navUtils.ts`

## Orientation

Chosen by `LayoutSettingsProvider` (see [`5.LayoutSettings`](5.LayoutSettings.md)) — persisted per storage key.

- **Vertical** (default) — side rail with optional density.
- **Horizontal** — top nav row below the header (auto-forced to vertical on mobile).

## SidebarVertical

Three density modes:

| Density     | Width               | Behavior                                                            |
|-------------|---------------------|---------------------------------------------------------------------|
| `expanded`  | `SIDEBAR_WIDTH`     | Full labels, inline nested tree via `Collapse`.                     |
| `compact`   | `SIDEBAR_COMPACT_WIDTH` | Icon + label, children open as a flyout `<Menu>`.                |
| `collapsed` | `SIDEBAR_COLLAPSED_WIDTH` | Icon-only rail; children flyout on click.                     |

### Active-branch handling

`navUtils.ts` exposes three pure helpers that both sidebars reuse:

```ts
isPathActive(currentPath, itemPath)          // exact or startsWith
isGroupActive(item, currentPath)             // recursive descend
hasActiveDescendant(item, currentPath)       // alias for isGroupActive
getInitialExpandedGroups(navigation, path)   // Record<key, true> for the initial state
```

The vertical sidebar seeds `expandedGroups` from `getInitialExpandedGroups` on mount and **merges** additional
initial-expanded entries on every route change (`useEffect([location.pathname, navigation])`). This means:

- Deep-links open the containing group automatically.
- Groups the user opened manually stay open across navigations (merge, don't overwrite).

### Active leaf / active group styling

Two separate helpers, on purpose:

- `getActiveLeafSx(raccoon, nested)` — the selected page (glow indicator, primary color).
- `getActiveGroupSx(raccoon)` — a parent whose descendant is selected (softer indicator, no glow).

Keeping them visually distinct prevents the "everything looks selected" fatigue in deep nav trees.

### Drawer variant

On mobile (`< LAYOUT_MOBILE_BREAKPOINT`) the sidebar is rendered inside a MUI `<Drawer>` at `expanded` density with
`variant="drawer"`. The drawer closes automatically when the user navigates via `onNavigate`.

## SidebarHorizontal

Renders the top-level nav items in a horizontal scrolling row. Groups become menu buttons with a dropdown; leaves
are plain `<Button component={NavLink}>`.

The whole component sits below the `LayoutHeader` and above the `<main>` content. Its `zIndex` (`layoutZIndex.sidebar`)
is intentionally below the header so page scroll shadow from the header still overlays it.

## Design notes

- The two sidebars **do not share** `sx` helpers. `getActiveLeafSx` and `getActiveGroupSx` are duplicated once per
  file (as `getHorizontalLeafSx` / `getHorizontalGroupSx`) because the two implementations diverged in what
  "active" should look like (side rail vs. top bar). Sharing would require a bag of conditional flags.
- `getInitialExpandedGroups` is pure and deterministic — safe to call in a `useState` initializer.
