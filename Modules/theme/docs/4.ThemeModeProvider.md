# 4. ThemeModeProvider

Owns the `light | dark` state, persists the user's manual choice, and follows OS preference until they make one.

- **Package:** `@raccoonland/theme`
- **File:** `src/ThemeModeProvider.tsx`

## Public API

```ts
type ThemeMode = 'light' | 'dark'
type PreferredThemeMode = ThemeMode | 'system'

<ThemeModeProvider
  defaultMode="system"                        // ThemeMode | 'system' — default: 'system'
  storageKey="raccoonland-theme-mode"         // per-app localStorage key
>
  {children}
</ThemeModeProvider>

const { mode, setMode, toggleMode } = useThemeMode()
```

- `mode` is always resolved to `light` or `dark`; consumers never see `'system'`.
- `setMode(next)` sets and persists an explicit choice.
- `toggleMode()` flips between light and dark.

## State machine

```text
mount ─┬─ localStorage has 'light' | 'dark' → use it,  userChose = true
       ├─ defaultMode === 'system'          → matchMedia('(prefers-color-scheme: dark)'),  userChose = false
       └─ else                               → defaultMode,  userChose = false

setMode / toggleMode → persist + userChose = true
storage event
  ├─ newValue is 'light' | 'dark'  → adopt, userChose = true
  └─ key cleared / newValue null    → fall back to system/default, userChose = false
matchMedia change
  └─ only applied while userChose === false
```

The `userChose` flag lives in a `useRef` — updates to it must not trigger a render.

## Cross-tab sync

The provider listens on `window.storage`. If tab A calls `setMode('dark')`, tab B's provider adopts `'dark'` too.
Clearing the key in any tab reverts every tab to system/default. This matches the pattern used by
[`LocaleProvider`](../../../Samples/Backoffice/src/i18n/LocaleProvider.tsx) in the sample.

## Safe storage access

All `localStorage` reads and writes are wrapped in try/catch — private-mode Safari, disabled storage, and
site-isolation errors do not crash the provider. State still works; only persistence is skipped.

## SSR / no-window

- `readSystemMode()` returns `'dark'` when `window` or `matchMedia` is missing (SSR / tests).
- `readStoredMode()` returns `null` on any error.
- `persistMode()` swallows storage errors silently.

## Wiring in a host

Mount **above** the theme-consuming tree, typically at the very top level:

```tsx
createRoot(rootElement).render(
  <StrictMode>
    <LocaleProvider>
      <ThemeModeProvider defaultMode="system" storageKey="raccoonland-sample-theme">
        <App />
      </ThemeModeProvider>
    </LocaleProvider>
  </StrictMode>,
)
```

Then in `AppProviders`:

```tsx
const { mode } = useThemeMode()
const theme = useMemo(() => createRaccoonTheme(direction, mode), [direction, mode])
```

## Design notes

- The provider exports both `setMode` (explicit) and `toggleMode` (convenience) because most UIs only need the
  toggle, but Settings pages benefit from the direct setter for radio-group patterns (see
  `Modules/layout/src/LayoutSettingsPanel.tsx`).
- `defaultMode="system"` is the recommended default: it respects OS preference until the user makes a decision,
  then stays out of the way.
