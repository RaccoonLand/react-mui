# 2. RaccoonTokens

The design-token contract consumed by every RaccoonLand shell component (Header, Sidebar, Page, Dialog, ...) via
`theme.raccoon`.

- **Package:** `@raccoonland/theme`
- **File:** `src/tokens.ts`

## Shape

```ts
export type RaccoonTokens = {
  primary:   { main: string; light: string; dark: string; contrastText: string }
  secondary: { main: string; light: string; dark: string; contrastText: string }

  background: {
    default:  string
    paper:    string
    elevated: string   // used for popovers, menus, panels above `paper`
    header:   string   // sticky app / page headers (usually semi-transparent)
  }

  text: {
    primary:   string
    secondary: string
    disabled:  string
  }

  divider: string
  border: {
    glow:   string  // used for focus / active accents (drop-shadow color)
    subtle: string  // 1px dividers between shell surfaces
  }

  input: {
    bg:            string
    border:        string
    borderHover:   string
    borderFocus:   string
  }

  error:   { main: string }
  success: { main: string }

  overlay:       string  // modal / drawer scrims
  shellGradient: string  // multi-radial gradient painted on the body backdrop

  nav: {
    activeBg:              string
    activeGroupBg:         string
    activeBorder:          string
    activeIndicatorWidth:  number
  }
}
```

## Presets

Both are exported at module level:

```ts
export const lightTokens: RaccoonTokens
export const darkTokens:  RaccoonTokens

export function getRaccoonTokens(mode: ThemeMode): RaccoonTokens
```

`getRaccoonTokens` is what `createRaccoonTheme` uses internally. Import it directly when you need tokens outside
React (e.g. Storybook stories, canvas-drawn components).

## Why these fields exist

| Token                       | Consumer(s)                                         | Why it isn't in `theme.palette`                     |
|-----------------------------|-----------------------------------------------------|-----------------------------------------------------|
| `background.header`         | LayoutHeader, Page sticky header, AppDrawer         | Needs a distinct semi-transparent variant.          |
| `background.elevated`       | Menus, Popovers, panels above `paper`               | MUI has only `default`/`paper`.                     |
| `border.glow`               | Active nav indicator shadow, focus emphasis         | Not a palette color; drop-shadow-friendly rgba.     |
| `border.subtle`             | 1px dividers everywhere in the shell                | Distinguishes shell chrome from `divider`.          |
| `input.*`                   | MUI OutlinedInput override                          | Groups the four states hoveredly used together.     |
| `overlay`                   | LoadingProvider backdrop                            | Not a palette entry; must match tone per mode.      |
| `shellGradient`             | Backoffice shell background                         | Multi-line CSS gradient string.                     |
| `nav.*`                     | SidebarVertical / SidebarHorizontal                 | Nav has its own visual language.                    |

## Design notes

- **Brand primary is invariant across modes** (`#9b4dff` with a slightly different `dark` in each mode). The two
  presets tune surrounding neutrals, not the brand ramp itself. If you need per-tenant branding, override via
  `createRaccoonTheme(direction, mode, { raccoon: { primary: {...} }, palette: { primary: {...} } })`.
- Tokens are **plain data**, not functions. This is what allows the `createRaccoonTheme` result to be safely
  memoized by `(direction, mode)` — no closure identity to worry about.
