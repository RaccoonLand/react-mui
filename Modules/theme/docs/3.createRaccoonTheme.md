# 3. createRaccoonTheme

The theme factory. Turns `(direction, mode, overrides?)` into an MUI `Theme` with `theme.raccoon` attached.

- **Package:** `@raccoonland/theme`
- **File:** `src/createRaccoonTheme.ts`

## Signature

```ts
export function createRaccoonTheme(
  direction: Direction,          // 'ltr' | 'rtl'
  mode: ThemeMode,               // 'light' | 'dark'
  overrides?: ThemeOptions,      // deep-merged into the base options
): Theme
```

## What it does

1. Picks the token set with `getRaccoonTokens(mode)`.
2. Chooses a font stack that puts the primary script first (`Vazirmatn` for RTL, `Inter` for LTR).
3. Builds `palette`, `typography`, `shape`, and a curated set of `components` overrides — the ones that would
   otherwise have to be repeated in every consuming app (`MuiOutlinedInput`, `MuiButton`, `MuiFormHelperText`,
   `MuiListItemButton`, ...).
4. Attaches the raw token set to `theme.raccoon` via module augmentation.

## Deep-merged overrides

If `overrides` is provided, it is passed as a **second argument** to MUI's `createTheme`:

```ts
createTheme({ direction, raccoon, palette, ..., components }, overrides)
```

`createTheme` uses its internal `deepmerge` on multiple option arguments. This means overriding a slice does not
delete siblings — e.g. `{ palette: { primary: { main: '#f00' } } }` only touches `primary.main`; `secondary`,
`background`, `text`, `divider`, `error`, `success` keep the raccoon values.

An earlier version of this factory spread `...overrides` inside a single options object, which had the opposite
behavior: setting `palette.primary` would wipe out every other palette key. Do **not** revert to the spread form.

## Caching

The factory memoizes results in a module-level `Map<'${direction}:${mode}', Theme>`:

- Cache is consulted only when `overrides` is `undefined` — themes with call-site overrides are treated as unique
  and never cached.
- Cache is populated by first call. Subsequent calls with the same `(direction, mode)` return the same `Theme`
  reference, so `<ThemeProvider>` receives an unchanged value and skips the descendant re-render cascade.

The sample app also **warms the cache** for the opposite combos in an idle callback (see `AppProviders`), so the
first user-triggered theme/language toggle hits the cache instead of computing on the main thread mid-toggle.

## Usage

```tsx
const theme = useMemo(() => createRaccoonTheme(direction, mode), [direction, mode])
return <ThemeProvider theme={theme}>{children}</ThemeProvider>
```

With overrides:

```ts
createRaccoonTheme('rtl', 'dark', {
  raccoon: {
    ...darkTokens,
    primary: { main: '#22d3ee', light: '#67e8f9', dark: '#0891b2', contrastText: '#001217' },
  },
  palette: {
    primary: { main: '#22d3ee', light: '#67e8f9', dark: '#0891b2', contrastText: '#001217' },
  },
})
```

(Both `raccoon.primary` and `palette.primary` are set because shell components read from `theme.raccoon` while MUI
built-ins read from `theme.palette`.)

## Module augmentation

The `declare module '@mui/material/styles'` block that adds `raccoon: RaccoonTokens` to `Theme` / `ThemeOptions`
lives **next to the factory** so any consumer importing from `@raccoonland/theme` picks it up automatically. There
is no side-effect-only `.d.ts` to remember to import.
