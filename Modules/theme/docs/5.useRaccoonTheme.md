# 5. useRaccoonTheme

Typed access to `theme.raccoon` from any component under a `<ThemeProvider>`.

- **Package:** `@raccoonland/theme`
- **File:** `src/useRaccoonTheme.ts`

## Signature

```ts
export function useRaccoonTheme(): RaccoonTokens
```

## What it does

```ts
const theme = useTheme()
const raccoon = (theme as { raccoon?: RaccoonTokens }).raccoon
if (!raccoon) {
  throw new Error(
    '@raccoonland/theme: theme.raccoon is missing. Wrap your app with ' +
      'MUI <ThemeProvider theme={createRaccoonTheme(direction, mode)}>.',
  )
}
return raccoon
```

The explicit throw exists so setup mistakes surface with a **clear diagnostic**. Without it, downstream code would
crash on `theme.raccoon.background.header` with an opaque `"Cannot read properties of undefined (reading 'background')"`
message that hides the real cause.

## When to use it

Use `useRaccoonTheme()` when you need one of the shell-only tokens (`background.header`, `border.glow`, `nav.*`,
`shellGradient`, `overlay`, `input.*`). Everything else should keep using MUI's `useTheme()` / the `sx` prop —
values like `text.primary`, `divider`, `primary.main` are wired into `theme.palette` for you, and the token
values feed those palette entries.

## Example

```tsx
function ShellSurface({ children }: { children: ReactNode }) {
  const raccoon = useRaccoonTheme()
  return (
    <Box
      sx={{
        bgcolor: raccoon.background.paper,
        borderBottom: `1px solid ${raccoon.border.subtle}`,
        backgroundImage: raccoon.shellGradient,
      }}
    >
      {children}
    </Box>
  )
}
```

## Referential stability

`raccoon` is a plain object attached to the `Theme`, which itself is memoized by `createRaccoonTheme` on
`(direction, mode)`. Consequently `useRaccoonTheme()` returns the **same reference** across renders that share the
same `(direction, mode)` — this is important for downstream `useMemo` deps (see for example
`Modules/form-kit/src/FormPersianDatePicker.tsx`'s `usePickerColors` memo).
