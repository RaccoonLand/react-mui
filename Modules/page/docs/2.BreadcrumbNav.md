# 2. BreadcrumbNav

MUI `Breadcrumbs` bound to `react-router` links, with direction-aware separator mirroring.

- **Package:** `@raccoonland/page`
- **File:** `src/BreadcrumbNav.tsx`

## Props

```ts
type BreadcrumbItem = {
  label: string
  href?: string                 // Missing href → not a link
  icon?: SvgIconComponent
}

type BreadcrumbNavProps = {
  items: BreadcrumbItem[]
  direction?: 'ltr' | 'rtl'     // Default 'ltr'
}
```

## Behavior

- **Last crumb is never a link** — even if `href` is set on it, the last item renders as static text. This matches
  the aria pattern for breadcrumbs (current page should not be a link).
- **Direction mirroring** — the separator icon (`NavigateNextIcon`) is rotated 180° when `direction === 'rtl'` so
  the arrow points from parent to child in both directions.
- **Empty items → renders nothing** (returns `null`). Safe to always mount and hydrate the list conditionally.

## Icons

Icons come from `resolveBreadcrumbIcon(item)` — which currently returns `item.icon` unchanged. The indirection is
kept so a future rule could resolve icons by `href` pattern or by route metadata without touching call sites.

## Current-page emphasis

The final crumb gets a subtle pill background, slightly bolder text, and its icon uses `primary.main`. This makes
the current page visually distinct from the trail even at small font sizes.

## Design notes

- The link renders as `component={NavLink from react-router-dom}` inside a MUI `Link` so both router semantics
  (active class, prefetch on hover) and MUI styling work together.
- No i18n inside; all labels are pre-translated by the caller.
