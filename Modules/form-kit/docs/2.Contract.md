# 2. Contract & helpers

The small shared surface every `FormXxx` obeys, plus the value-normalization utilities the whole kit relies on.

- **Package:** `@raccoonland/form-kit`
- **Files:** `src/types.ts`, `src/fieldError.ts`, `src/valueNormalization.ts`

## Naming contract

```ts
export type FormControlNameProps<T extends FieldValues> = {
  name: FieldPath<T>
}
```

Every component takes exactly one required prop: `name`, typed against the form's `T` so autocomplete and
compile-time checks work end-to-end. RHF's `Controller` and `useFormContext<T>()` are used inside; the caller never
passes `control`.

## Option contract

```ts
export type FormOption<T = string | number> = {
  value: T
  label: string
  disabled?: boolean
}

export type ValueAs = 'string' | 'number'
```

Every selection control (`FormSelect`, `FormMultiSelect`, `FormRadioGroup`, `FormAutocomplete`,
`FormCheckboxGroup`, `FormToggleButtonGroup`, `FormTransferList`) consumes a `FormOption[]` and a `valueAs`
setting. The library normalizes user selections to strings (default) or coerces to numbers when `valueAs="number"`.

## Error surface

```ts
export function getFieldErrorProps(error?: FieldError): {
  error: boolean
  helperText: string | undefined
  FormHelperTextProps: { role?: 'alert' }
}
```

Guarantees consistent semantics for every control:

- `error` — a boolean for the MUI `error` prop.
- `helperText` — the RHF `error.message`, or `undefined` when the field is valid.
- `FormHelperTextProps.role` — set to `'alert'` when in error state so screen readers announce it.

Consumers usually spread this alongside their own props:

```tsx
const errorProps = getFieldErrorProps(fieldState.error)
<TextField
  {...fieldProps}
  {...errorProps}
  helperText={errorProps.helperText ?? textFieldProps?.helperText}
  FormHelperTextProps={{ ...textFieldProps?.FormHelperTextProps, ...errorProps.FormHelperTextProps }}
/>
```

## Value normalization

`src/valueNormalization.ts` centralizes the coercion rules:

| Helper                       | Purpose                                                                                             |
|------------------------------|-----------------------------------------------------------------------------------------------------|
| `normalizeTextValue(v)`      | `null / undefined → ''`; else `String(v)`. Prevents "controlled → uncontrolled" warnings.           |
| `normalizeSelectValue(v, as)`| `null / undefined / '' → ''`. Coerces to number when `as === 'number'`; NaN → `''`.                 |
| `coerceSelectChange(raw, as)`| Empty string stays empty (avoids `Number('') === 0` bug). Coerces to number when applicable.        |
| `normalizeMultiSelectValue`  | Always an array; each entry coerced via the single-value rules.                                     |
| `coerceMultiSelectChange`    | Accepts `string | string[]`, returns coerced array.                                                 |
| `normalizeBooleanValue(v)`   | `Boolean(v)`. Guards against `null` / `undefined` in checkbox / switch controls.                    |
| `emptyToNull(v)`             | Convert empty optional strings to `null` before API submit. Trim-aware.                             |

The subtle-but-important rule enforced across the kit: **empty is not zero**. `coerceSelectChange('', 'number')`
returns `''`, not `0`. Without this, an unselected numeric option would write `0` into the form state.

## Referential stability

- The helpers are all pure functions returning primitives / arrays. They are safe to call inline in a render.
- The kit intentionally does **not** cache their outputs — the values are cheap and caching them would leak
  form-state identity across unrelated fields.
