# 1. Overview

`@raccoonland/form-kit` is a set of React Hook Form × MUI bindings covering every input the backoffice needs. Every
control:

- Consumes RHF via `useFormContext<T>()` + `<Controller>`.
- Reads validation state and renders MUI `error` / `helperText` consistently.
- Normalizes values (empty ↔ `null`, `number | string` via `valueAs`, boolean coercion).
- Accepts pass-through props for the underlying MUI component (`textFieldProps`, `sliderProps`, ...).

- **Package:** `@raccoonland/form-kit`
- **Peer deps:** `react`, `react-dom`, `react-hook-form`, `@mui/material`, `@mui/icons-material`,
  `@mui/x-date-pickers`, `dayjs`, `react-multi-date-picker`

## Catalog

| Group                     | Components                                                                             |
|---------------------------|----------------------------------------------------------------------------------------|
| Text & selection          | `FormTextField`, `FormSelect`, `FormMultiSelect`, `FormRadioGroup`, `FormAutocomplete`, `FormAsyncAutocomplete` |
| Boolean & scale           | `FormCheckbox`, `FormCheckboxGroup`, `FormSwitch`, `FormToggleButtonGroup`, `FormSlider`, `FormRating` |
| Date & time               | `FormDatePicker`, `FormTimePicker`, `FormDateTimePicker`, `FormPersianDatePicker`, `FormDateLocalizationProvider` |
| Files & color             | `FormFileUpload` (drag & drop), `FormColorPicker`                                      |
| Rich & tag input          | `FormRichText` (with built-in XSS defense), `FormChipInput`, `FormTransferList`        |

Utility exports (shared with app code and other packages):

- `getFieldErrorProps(error)` — turns an RHF `FieldError` into `{ error, helperText, FormHelperTextProps }`.
- `normalizeTextValue`, `normalizeSelectValue`, `coerceSelectChange`, `normalizeMultiSelectValue`,
  `coerceMultiSelectChange`, `normalizeBooleanValue`, `emptyToNull`.
- Types: `FormControlNameProps<T>`, `FormOption`, `ValueAs`.

## Layering

```text
Host form (RHF FormProvider)
  └── <FormXxx name="..." ... />       (from @raccoonland/form-kit)
        └── Controller                  (RHF)
              └── MUI control           (@mui/material)
```

Every `FormXxx` requires a RHF `FormProvider` above it (that's what `useFormContext()` reaches for). If your form
does not use FormProvider you can still consume the underlying MUI components directly.
