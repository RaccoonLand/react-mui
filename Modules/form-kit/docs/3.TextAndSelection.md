# 3. Text & selection controls

Text input, single- and multi-value selection, and typeahead.

- **Package:** `@raccoonland/form-kit`
- **Files:** `src/FormTextField.tsx`, `src/FormSelect.tsx`, `src/FormMultiSelect.tsx`, `src/FormRadioGroup.tsx`, `src/FormAutocomplete.tsx`, `src/FormAsyncAutocomplete.tsx`

## FormTextField

Thin binding over `@mui/material` `TextField` — controlled by RHF, normalizes `field.value` with `normalizeTextValue`.

```tsx
<FormTextField<UserForm> name="email" label={t('email')} type="email" />
```

Every `TextFieldProps` prop passes through (except `name` / `defaultValue` / `value`, which RHF owns).

## FormSelect

`TextField select` bound to RHF. Options may be provided as `options={[...]}` for the common case or as `children`
if you need custom `<MenuItem>` markup.

```tsx
<FormSelect<UserForm>
  name="role"
  label={t('role')}
  options={roleOptions}
  valueAs="string"
/>
```

`valueAs="number"` stores the selected value as a number in the form state (with empty-string protection — see
`coerceSelectChange`).

## FormMultiSelect

Multi-select variant. Checkbox left of each item by default (`showCheckbox={true}`), and the rendered value in the
input is a comma-separated join of the selected labels.

```tsx
<FormMultiSelect<Filter>
  name="tagIds"
  label={t('tags')}
  options={tags}
  valueAs="number"
/>
```

Form state shape: `Array<string | number>` — coerced according to `valueAs`.

## FormRadioGroup

Standard radio group with a shared `name`, `label`, `row`, and `disabled`. Uses the same `valueAs` semantics as
`FormSelect`.

```tsx
<FormRadioGroup<Preferences>
  name="notification"
  label={t('notification')}
  row
  options={notificationOptions}
/>
```

## FormAutocomplete

MUI `Autocomplete` bound to RHF with a couple of value shape switches.

Props of note:

- `multiple?: boolean` — single vs. multi selection.
- `valueAsPrimitive?: boolean` — **default `true`**. When `true`, form state holds `option.value` (or an array of
  values) instead of full `FormOption` objects. Turn off when you need the whole object for downstream logic.
- `options: FormOption[]` — the searchable list.
- Same `textFieldProps` merge rules as `FormAsyncAutocomplete` (see below).

Single-value example:

```tsx
<FormAutocomplete<UserForm>
  name="managerId"
  label={t('manager')}
  options={managerOptions}
/>
```

Multi-value:

```tsx
<FormAutocomplete<Filter>
  name="tags"
  label={t('tags')}
  multiple
  options={tagOptions}
/>
```

## FormAsyncAutocomplete

Server-driven typeahead. The package owns debounce, loading, request cancellation / races, and keeping the
selected option visible when it is not in the latest result set. The host only supplies `loadOptions`.

Props of note:

- `loadOptions: (query, signal) => Promise<FormOption[]>` — fetch implementation (honor `signal.aborted`).
- `debounceMs?: number` — default `300`.
- `minInputLength?: number` — default `0` (empty query is allowed).
- `defaultOptions?: FormOption[]` — seed labels for an existing form value (edit screens).
- `loadOnOpen?: boolean` — default `true`; set `false` to wait until the user types.
- `valueAsPrimitive` / `multiple` — same contract as `FormAutocomplete`.
- Client-side `filterOptions` is a no-op (server already filtered).
- Prefer `size="small"` (Autocomplete + `textFieldProps={{ size: 'small' }}`) next to PageFilter `TextField`s.

```tsx
<FormAsyncAutocomplete<UserForm>
  name="managerId"
  label={t('manager')}
  size="small"
  fullWidth
  defaultOptions={managerId ? [{ value: managerId, label: managerName }] : []}
  loadOptions={async (query, signal) => {
    const rows = await peopleApi.search(query, { signal })
    return rows.map((row) => ({ value: row.id, label: row.name }))
  }}
  textFieldProps={{
    size: 'small',
    inputProps: { maxLength: 128 }, // merged with Autocomplete params — safe
  }}
/>
```

### `textFieldProps` + Autocomplete wiring

`FormAutocomplete` / `FormAsyncAutocomplete` **merge** host `textFieldProps.inputProps` / `InputProps` /
`inputRef` with MUI Autocomplete `params`. Do not reinvent `renderInput` that replaces `params.inputProps`
outright — that drops Autocomplete’s input ref/ARIA and throws
`Cannot read properties of null (reading 'removeAttribute')` (especially under React 19 unmount).

RHF `field.ref` is composed with Autocomplete’s `InputProps.ref` via `mergeRefs`.

## Design notes

- Every text-based control routes MUI's `helperText` through `getFieldErrorProps`, so error messages appear in the
  standard slot and are announced via `role="alert"` for screen readers.
- `FormAutocomplete` / `FormAsyncAutocomplete` compare options by `String(option.value)` so form state can be
  primitives without breaking equality.
- Empty selections normalize to `''` (not `null`), matching MUI's expectation for uncontrolled selects. Call
  `emptyToNull(value)` before submitting if your API requires `null`.
- For async edit forms, pass `defaultOptions` (or ensure the first `loadOptions` hit includes the current value)
  so the selected label renders before the user opens the popup.
