# 7. Rich text, chips, and transfer lists

The higher-composition inputs — rich text editing with mentions, chip input for free-form tags, and a two-column
transfer list.

- **Package:** `@raccoonland/form-kit`
- **Files:** `src/FormRichText.tsx`, `src/FormChipInput.tsx`, `src/FormTransferList.tsx`

## FormRichText

A `contentEditable`-based rich-text editor with bold / italic / underline / bulleted list, and an optional
mention popover triggered by typing `@`.

```tsx
<FormRichText<Post>
  name="body"
  label={t('body')}
  placeholder={t('typeHere')}
  mentionOptions={teamMembers}
  minHeight={200}
/>
```

Form state shape: an HTML `string`. Empty content is stored as `''` (not `'<br>'`).

### XSS defense

The editor is a genuine XSS sink when `field.value` is prefilled from an untrusted source (server response, URL
params, saved draft from another user). Writing that value into a `contentEditable` via `innerHTML` executes
payloads like `<img src=x onerror=...>` on load.

The kit ships a small, **dependency-free** sanitizer (`sanitizeRichTextHtml`) that:

1. Restricts tags to `A, B, STRONG, I, EM, U, S, STRIKE, BR, P, DIV, SPAN, UL, OL, LI`. Everything else (`script`,
   `iframe`, `object`, `embed`, `style`, `link`, `meta`, `form`, `img`, `svg`, ...) is dropped.
2. Strips every `on*` event handler attribute.
3. Removes `href` / `src` / `xlink:href` whose value starts with `javascript:` (case-/whitespace-insensitive).
4. Preserves `data-*` and `aria-*` attributes so mention spans (`data-mention="..."`) and accessibility hints
   survive.

Sanitization runs in **both directions**:

- On read (before `innerHTML = value`) — primary defense against untrusted prefill.
- On write (`emitChange` / `onInput`) — catches HTML pasted by the user and any `execCommand` corner cases.

This is defense-in-depth. Servers must still sanitize on write.

### Deprecation note

The formatting toolbar uses `document.execCommand` (bold / italic / underline / insertUnorderedList). This API is
marked "obsolete" by MDN but still works everywhere. Replacing it is a rewrite, not a patch — deferred until a
browser actually removes it.

## FormChipInput

Free-form tag input built on MUI `Autocomplete` with `multiple` and `freeSolo`.

```tsx
<FormChipInput<Filter>
  name="tags"
  label={t('tags')}
  options={suggestedTags}      // optional autocomplete suggestions
  placeholder={t('addTag')}
/>
```

Form state shape: `string[]`. Chips are trimmed and deduped (case-sensitive) on every change.

## FormTransferList

Two-column list with move-selected-right / move-selected-left buttons. Useful for permission editors and role-mapping
UIs.

```tsx
<FormTransferList<Role>
  name="permissions"
  label={t('permissions')}
  options={allPermissions}
  valueAs="string"
  leftTitle={t('available')}
  rightTitle={t('assigned')}
/>
```

Form state shape: `Array<string | number>` — matches `FormCheckboxGroup` / `FormMultiSelect` so lists are
interchangeable across UIs.

Header of each column shows the current "checked / total" count and a master checkbox with `indeterminate`
support.

### State model

- The **field value** (RHF) holds the "right" (selected) list. The "left" list is derived at render time as
  `allValues - selected`.
- The **checked** state (which rows are marked for transfer) is local to the component. It survives moves
  (staying on the moved rows for a moment is intentional) but is not persisted anywhere.

## Design notes

- `FormRichText` intentionally does not bring in DOMPurify. The editor's output surface is small enough that a
  strict allowlist is both simpler to read and unambiguously safe for this use case. If you need to allow embedded
  images or iframes, upgrade to a full sanitizer at that point.
- `FormTransferList`'s local `checked` state is **not** cleared when the form is reset. That's a deliberate trade
  — resetting the form should not silently move rows the user staged for transfer.
