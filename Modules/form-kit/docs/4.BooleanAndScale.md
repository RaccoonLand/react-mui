# 4. Boolean & scale controls

Checkboxes, switches, toggle groups, sliders, and ratings.

- **Package:** `@raccoonland/form-kit`
- **Files:** `src/FormCheckbox.tsx`, `src/FormCheckboxGroup.tsx`, `src/FormSwitch.tsx`, `src/FormToggleButtonGroup.tsx`, `src/FormSlider.tsx`, `src/FormRating.tsx`

## FormCheckbox

Single boolean checkbox with a label. Form state is a `boolean`.

```tsx
<FormCheckbox<UserForm> name="acceptedTerms" label={t('acceptTerms')} />
```

## FormCheckboxGroup

An array of checkboxes bound to a single field. Form state is `Array<string | number>` (coerced by `valueAs`).

```tsx
<FormCheckboxGroup<Filter>
  name="statuses"
  label={t('statuses')}
  row
  options={statusOptions}
  valueAs="string"
/>
```

## FormSwitch

Same contract as `FormCheckbox`, rendered as a switch. Prefer for on/off settings; prefer `FormCheckbox` for
list-of-options patterns.

```tsx
<FormSwitch<Preferences> name="darkMode" label={t('darkMode')} />
```

## FormToggleButtonGroup

`ToggleButtonGroup` bound to RHF. Two modes:

- `exclusive={true}` (default) — single value; form state is `string | number`.
- `exclusive={false}` — multi-value; form state is `Array<string | number>`.

```tsx
<FormToggleButtonGroup<Filter>
  name="density"
  label={t('density')}
  exclusive
  options={densityOptions}
/>
```

## FormSlider

Range-aware slider. Two modes:

- `range={false}` (default) — form state is `number`.
- `range={true}` — form state is `[min, max]` (`number[]` of length 2).

```tsx
<FormSlider<Filter>
  name="priceRange"
  label={t('priceRange')}
  range
  sliderProps={{ min: 0, max: 1000, step: 10, valueLabelDisplay: 'auto' }}
/>
```

`onChangeCommitted` triggers `field.onBlur()` so validation errors that need "blur to appear" behave correctly on
sliders.

## FormRating

MUI `Rating` bound to RHF. Form state is `number | null` (null on clear).

```tsx
<FormRating<Feedback> name="score" label={t('score')} />
```

Non-numeric field values are coerced with `Number(...)`; `NaN` is coerced back to `null` so the rating displays as
"empty".

## Design notes

- All controls in this group render an outer `<FormControl>` with `error` / `disabled` wired, plus a
  `<FormHelperText role="alert">` when there's an RHF error. Layouts stay consistent across the whole form.
- `FormCheckboxGroup` used to be defined with `component="fieldset"` but MUI's typing for that mode narrows
  `onChange` in a way that clashes with our nested checkbox handler. The current implementation uses
  `variant="standard"` on a `div` and applies the fieldset semantics via nested `FormLabel component="legend"` —
  same accessibility, no type friction.
