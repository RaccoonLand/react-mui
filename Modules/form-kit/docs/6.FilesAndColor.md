# 6. File upload & color picker

Two utility inputs that don't fit any of the other groupings.

- **Package:** `@raccoonland/form-kit`
- **Files:** `src/FormFileUpload.tsx`, `src/FormColorPicker.tsx`

## FormFileUpload

File input with drag-and-drop, single/multiple selection, MIME/extension filtering, and a preview list.

### Props (highlights)

```ts
type FormFileUploadProps<T> = {
  name: FieldPath<T>
  label?: string
  disabled?: boolean
  multiple?: boolean       // default false
  accept?: string          // "image/*,application/pdf,.csv" — same format as native <input>
  buttonLabel?: string     // default "Choose file"
  emptyLabel?: string      // default "No file selected"
  dropLabel?: string       // default "Drag & drop files here, or click to browse"
  enableDrop?: boolean     // default true — false hides the dropzone (button-only)
  formControlProps?: ...
}
```

### Form state shape

- `multiple={false}` — `File | null`.
- `multiple={true}`  — `File[]` (deduped by `${name}:${size}:${lastModified}`).

### Drag-and-drop

Uses `onDragEnter`/`onDragOver`/`onDragLeave`/`onDrop` with a **depth counter** (`dragDepth` ref) so nested
elements inside the dropzone don't produce phantom drag-leave events when the pointer moves between children.

`onDragOver` explicitly sets `event.dataTransfer.dropEffect = 'copy'` so the browser cursor shows the correct
affordance.

### `accept` filtering

Client-side filter mirrors the native `<input accept>` semantics:

- `.png`, `.pdf`, ...    → suffix match on file name.
- `image/*`, `video/*`   → prefix match on MIME.
- `application/json`, ... → exact MIME match.

The native input already respects `accept`, but drag-and-drop drops bypass that check — so the same filter runs
again inside `applyFiles`. Files that don't match are silently ignored (no toast, no error).

### Merge semantics for `multiple`

New drops **add to** the existing selection, deduped. If a user drops the same file twice, or drops file A after
already having file A, only one entry remains. Use the trash icon on each row to remove.

### Reset after selection

After every `<input>` change, `input.value = ''` runs so that selecting the same path a second time in a row
still triggers `onChange`. This is a well-known native quirk.

## FormColorPicker

Native color input paired with a hex TextField. Both drive the same RHF field.

```tsx
<FormColorPicker<Preferences> name="accentColor" label={t('accent')} />
```

### Value shape

Free-form string in form state — usually a `#RRGGBB` hex, but not enforced. The swatch itself always resolves to a
valid 6-digit hex via `normalizeHex` (short `#RGB` is expanded; anything else falls back to `#000000`).

Server-side validation should still verify the format on submit — the client is permissive by design so users can
paste partial values without losing focus.

## Design notes

- `FormFileUpload` does **not** enforce a size or file-count limit. Bring your own check inside `onSubmit` (or a
  RHF validator). A limit prop is easy to add — deliberately deferred until a concrete need appears.
- Neither control stores anything in memory beyond the current selection; they are safe to drop from a form as
  soon as the field is submitted or reset.
