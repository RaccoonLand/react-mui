# 2. ToastProvider

Toast wrapper around `notistack` with direction-aware anchoring and an action-button slot.

- **Package:** `@raccoonland/feedback`
- **File:** `src/toast/ToastProvider.tsx`

## Public API

```ts
type ToastVariant = 'success' | 'error' | 'warning' | 'info'

type ToastAction = {
  label: string
  onClick: () => void
}

const {
  showToast,     // (message, variant | { variant, action })
  showSuccess,   // (message, action?)
  showError,     // (message, action?)
  showWarning,   // (message, action?)
  showInfo,      // (message, action?)
} = useToast()
```

Every method returns the `SnackbarKey` from notistack; callers rarely need it but it's useful for programmatic
dismissal.

## Provider props

```tsx
<ToastProvider
  direction="ltr"           // 'ltr' | 'rtl' — flips anchorOrigin.horizontal
  maxSnack={4}
  autoHideDuration={4000}   // ms; null → persistent until user dismisses
  preventDuplicate={true}
>
  {children}
</ToastProvider>
```

- `direction` maps to `anchorOrigin`: `top-right` (LTR) or `top-left` (RTL). The mapping is memoized so switching
  direction re-anchors without churning the provider tree.
- `maxSnack` is passed straight through to notistack.
- Setting `autoHideDuration={null}` makes toasts sticky — good for critical errors that the user must acknowledge.

## Action-button slot

Passing an `action` renders a button inside the snack that dismisses the toast on click:

```tsx
showError(t('failedToSaveDraft'), {
  label: t('retry'),
  onClick: () => save(),
})
```

The action's `onClick` runs first; then `closeSnackbar(snackbarId)` fires so the toast disappears without the user
having to click Close.

## Wiring pattern

Mount **once**, near the top of the tree, above anything that would fire toasts:

```tsx
<ToastProvider direction={direction} maxSnack={4} autoHideDuration={4000}>
  <LoadingProvider>
    ...
  </LoadingProvider>
</ToastProvider>
```

## Design notes

- The internal `ToastBridge` memoizes the `showToast/showSuccess/...` methods on `[enqueueSnackbar, closeSnackbar]`
  which notistack keeps referentially stable. This means components that receive these methods as props do not
  invalidate on every parent render.
- The provider does not localize anything — callers pass fully-localized strings. This keeps `@raccoonland/feedback`
  free of i18n concerns.
