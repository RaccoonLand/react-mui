# 5. AppDialog & AppDrawer

Structured wrappers over MUI's `Dialog` and `Drawer` that encode the shell's chrome (elevated background, glow
border, header with close button) and add a couple of ergonomics improvements.

- **Package:** `@raccoonland/feedback`
- **Files:** `src/overlay/AppDialog.tsx`, `src/overlay/AppDrawer.tsx`

## AppDialog

### Props (highlights)

```ts
type AppDialogProps = {
  open: boolean
  onClose: () => void
  title: ReactNode
  children: ReactNode
  actions?: ReactNode                // Rendered inside <DialogActions>
  maxWidth?: DialogProps['maxWidth'] // default 'sm'
  fullWidth?: boolean                // default true
  scroll?: DialogProps['scroll']     // default 'paper'
  dividers?: boolean                 // default true
  showCloseButton?: boolean          // default true
  closeLabel?: string                // aria-label for close icon
  variant?: 'default' | 'emphasis'   // 'emphasis' adds glow border and stronger shadow
  contentSx?: SxProps<Theme>
  onConfirm?: () => void             // enables Enter-to-confirm
  disableRestoreFocus?: boolean
}
```

### Enter-to-confirm

If `onConfirm` is provided, the dialog installs a `window`-level `keydown` listener that fires `onConfirm()` on
Enter — but **only** when:

1. The event target is **not** an input / textarea / select / contenteditable (`isTypingTarget`), and
2. The event target is **not** already inside a button / role=button / link (`isNativeEnterTarget`).

Guard #2 is important: when the user has focused the Cancel button and hits Enter, they expect Cancel to fire —
not the confirm. Letting Enter propagate to native activation preserves that contract.

### `variant="emphasis"`

Slightly stronger visual weight for confirmations and consequential prompts (uses `raccoon.border.glow` for both
border and box-shadow). Default is the "utility dialog" look.

### Focus restoration

`disableRestoreFocus` maps directly to MUI's Dialog prop. Set it when opening a dialog from a menu item that the
user does not want to be re-focused after close.

## AppDrawer

### Props (highlights)

```ts
type AppDrawerProps = {
  open: boolean
  onClose: () => void
  title: ReactNode
  children: ReactNode
  footer?: ReactNode                   // Rendered below a <Divider> at the bottom
  anchor?: DrawerProps['anchor']       // default 'right'
  width?: number                       // default 360; capped at 100vw
  closeLabel?: string
  contentSx?: SxProps<Theme>
  disableRestoreFocus?: boolean
}
```

The drawer always fills the viewport on `xs` (`width: '100%'`) and switches to the fixed `width` at `sm+`. The
inner header uses `raccoon.background.header` so it feels continuous with the shell header underneath.

## When to use which

| Situation                                                              | Component  |
|------------------------------------------------------------------------|------------|
| Ask for a decision (confirm / prompt) or show a modal form.            | AppDialog  |
| Show a large amount of detail alongside the main content.              | AppDrawer  |
| One-line notice / transient result.                                    | Toast      |

## Design notes

- Both components rely on `useRaccoonTheme()` for shell coloration — they do not accept arbitrary color overrides,
  by design. Consumers that need bespoke chrome should compose `<Dialog>` / `<Drawer>` directly.
- Neither component owns state: they are fully controlled by `open` / `onClose`. Keep dialog visibility state in
  the parent (or use `useConfirm()` for one-off confirmations).
