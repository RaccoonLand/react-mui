# 3. LoadingProvider

Promise-oriented loading indicator with a global backdrop, scoped tracking, and duplicate-flash suppression.

- **Package:** `@raccoonland/feedback`
- **File:** `src/loading/LoadingProvider.tsx`

## Public API

```ts
type LoadingScope = 'global' | 'local'

const { withLoading, isLoading, isAnyLoading } = useLoading()

// withLoading<T>(
//   action: () => Promise<T>,
//   options?: { scope?: LoadingScope; message?: string },
// ): Promise<T>
```

- `withLoading` returns the **same promise the action returns** — errors and cancellation propagate unchanged.
- `isLoading` is `true` while the **global backdrop** is on screen. Prefer this for disabling buttons that trigger
  global-scope actions. Local-scope in-flight work does not flip this signal.
- `isAnyLoading` is `true` while any scope has in-flight work. Useful for e2e tests and debugging.

## Behavior

- **Scope: global** — increments a counter, shows the `<Backdrop>`. The most recently registered `message` is what
  the backdrop displays; a message is popped from the stack when its work finishes, so the next visible message is
  always the topmost still-running one.
- **Scope: local** — bumps only the total pending count. No backdrop. Use for row-level or inline spinners the
  caller renders on its own; `useLoading` only tracks whether at least one such op is in-flight via
  `isAnyLoading`.
- **Minimum visible time** — a global backdrop that would otherwise flash for a few frames is held on screen for
  at least `LOADING_MIN_VISIBLE_MS` (50 ms). Prevents the annoying "did it just blink?" effect on fast requests.
- **Unmount safety** — the pending hide-timer is cleared on provider unmount so the backdrop never sets state
  after teardown.

## Overlap semantics

Two overlapping global-scope calls display one backdrop; the backdrop stays on screen until **both** finish. The
displayed `message` follows the most recent registrant, so the latest operation's copy wins.

```ts
await Promise.all([
  withLoading(() => saveHeader(input), { message: t('savingHeader') }),
  withLoading(() => saveLines(input),  { message: t('savingLines') }),
])
```

## Wiring with pipeline hooks

```tsx
// PipelineHooksBridge
const { withLoading } = useLoading()

<PipelineHooksProvider adapter={{
  toast:   { showError, showWarning },
  loading: { withLoading },
}}>
  {children}
</PipelineHooksProvider>
```

`usePipelineQuery` / `usePipelineMutation` then automatically drive the backdrop for every request without their
call sites having to think about it. See [`4.PipelineHooksProvider`](../../../Core/pipeline-client/docs/4.PipelineHooksProvider.md).

## Design notes

- Backdrop `zIndex` is `theme.zIndex.modal + 1` so it sits above `<Dialog>` / `<Menu>`. Bring your own custom
  overlays (e.g. spotlight tour) into this stack if they need to appear on top of the backdrop.
- The counter is a `useRef` — flipping counts must not force a render. The visible state uses `useState` and is
  updated only at transitions (0→1 shows, 1→0 hides after the minimum-visible-time timer).
